# End-to-end Tests and CI with Docker — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run the whole app in Docker, cover the main journeys with a Playwright suite in the repo, and check
everything on every push with GitHub Actions.

**Architecture:** API image (+ an EF migrations bundle stage), an nginx website image serving the Angular build over
HTTPS and proxying to the API, Postgres; one Compose file for the end-to-end stack; Playwright tests in
`frontend/e2e/`; one workflow with backend, frontend and e2e jobs.

**Tech Stack:** .NET 10, Angular 22, Postgres 16, nginx (alpine), Docker Compose, `@playwright/test` 1.64.0,
`@axe-core/playwright` 4.14.0, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-27-e2e-and-ci-design.md`

## Global Constraints

- No external services in tests or CI: GBIF, images, Pl@ntNet off via environment variables; identification is
  stubbed in the browser.
- Cookies stay `Secure`; CSRF stays on; forwarded headers only from `ForwardedHeaders:KnownNetworks`, off by default.
- No secrets in files or the workflow. The e2e Compose file's Postgres password is a fixed throwaway value for that
  stack only; the Postgres port is not published.
- Database name in the stack: `plant_encyclopedia_test` (allowed by the seed guard). Never touch the developer's dev
  database or its volume.
- Repo rules: no git commands that change state; "Commit" steps = run checks and suggest `git add`/`git commit`.
  Prettier only on files created or edited, except Task 5's three named templates.
- Each task ends green: backend `dotnet build` + `dotnet test` (Tasks 1–2), frontend `npx ng test --watch=false` +
  `npx ng build` (Tasks 4–5), the stack + suite (Tasks 3–4, 6).

## Review Focus

1. A request with `X-Forwarded-Proto: https` from an untrusted address must stay HTTP — tested in Task 2.
2. The stack must start when the developer's dev Postgres on 5433 is running — no published DB port (Task 3 check).
3. Re-running the suite on the same stack must not fail on an existing account — unique email per run (Task 4).
4. A failed e2e run must still tear the stack down and keep the report — `if: always()` steps (Task 6).
5. The Linux runner must load SkiaSharp natively — backend tests run in CI on ubuntu (Task 1, proved in Task 6's
   first run).

### Task 2: Opt-in forwarded headers

**Files:** Create `backend/PlantEncyclopedia.Api/Common/ForwardedHeadersSetup.cs`; modify `Program.cs`

**Interfaces:** `public sealed class ForwardedHeadersOptions { bool Enabled; string[] KnownNetworks }` bound from
section `ForwardedHeaders`; `IServiceCollection AddTrustedProxies(this IServiceCollection, IConfiguration)`;
`IApplicationBuilder UseTrustedProxies(this IApplicationBuilder)`. Invalid CIDR → startup exception.

- [ ] **Step 1: Failing tests** (TestServer with settings `ForwardedHeaders:Enabled=true`,
  `ForwardedHeaders:KnownNetworks:0=10.9.0.0/16`; set the connection's remote IP with a startup filter):
  - "trusted proxy's https is honoured": request over http from 10.9.0.5 with `X-Forwarded-Proto: https` to
    `GET /api/me` → response sets the `pe_antiforgery` and `XSRF-TOKEN` cookies (today: 500, not an SSL request).
  - "untrusted proxy is ignored": same from 203.0.113.7 → no `XSRF-TOKEN` cookie (500 or no cookie), proving the
    header was not applied.
  - "off by default": without the settings, the trusted-address request is not treated as https.
  - "bad network fails at startup": `KnownNetworks:0=not-a-cidr` → factory start throws `InvalidOperationException`.
- [ ] **Step 2:** Run — expected FAIL.
- [ ] **Step 3:** Implement with ASP.NET Core `ForwardedHeadersOptions` (`XForwardedFor | XForwardedProto`,
